# M1 work packets

## CG-M1-01 — Workspace command (coordinator-owned)

**Objective:** Establish the React/TypeScript workspace and record one reproducible install, development, build, and browser-test command.

**Owned paths:** `package.json`, lockfile, workspace configuration, package manifests, test-runner configuration.

**Non-goals:** Component behavior, gallery content, visual redesign, and Vennusign integration.

**Acceptance:** A clean checkout uses the recorded commands; the production build succeeds; a browser test can launch against the app.

**Evidence:** command transcript in the milestone ledger, including tool versions and a clean build result.

## CG-M1-02 — Control Base and foundation contracts (coordinator-owned)

**Objective:** Add the approved shared Control Base, default-token skin, SkinProvider, LocaleProvider, English label catalog, control registry, and example-state contracts required by later controls.

**Owned paths:** `packages/tokens/**`, `packages/react/src/foundation/**`.

**May consume, not edit:** workspace configuration; `apps/lab/**`.

**Non-goals:** Concrete form, overlay, navigation, or feedback controls.

**Acceptance:** Public contracts compile; the default skin resolves; registry entries have stable names and catalogs; the universal property/state vocabulary and forbidden `className`/`style` boundary are testable; no Vennusign import or naming appears in package source.

**Evidence:** type-check/build plus focused contract tests.

## CG-M1-03 — Gallery shell (sequential local-agent beta)

**Objective:** Replace the prototype entry with a React/TypeScript gallery shell and reusable example frame. This packet is deliberately divided into sequential sub-packets so each local-agent instruction has a small, exact file boundary. Do not dispatch a later sub-packet until the prior returned change is accepted by the coordinator.

**Shared non-goals:** Delivering final Core v1 controls; changing package configuration, lockfiles, foundation exports, token values, browser specifications, or test-runner files.

**May consume, not edit:** foundation exports and token values.

### CG-M1-03.1 — React bootstrap

**Owned paths:** `apps/lab/src/main.js`, `apps/lab/src/GalleryApp.tsx`.

**Outcome:** Replace the prototype runtime entry with a React entry point that renders a provider-backed gallery application.

**Acceptance:** The existing root entry loads the React application; `SkinProvider` and `LocaleProvider` wrap it; production build passes; no other path changes.

**Evidence:** `npm run build` result and changed-file list.

### CG-M1-03.2 — Gallery content

**Owned paths:** `apps/lab/src/GalleryApp.tsx`.

**Outcome:** Add the gallery title, description, and sections for Actions, Inputs, Overlays, Navigation, and Feedback.

**Acceptance:** Each planned family has a labelled destination in the gallery; the content is an empty shell, not a delivery of concrete controls.

**Evidence:** `npm run build` result and changed-file list.

### CG-M1-03.3 — Family navigation

**Owned paths:** `apps/lab/src/FamilyNavigation.tsx`.

**Outcome:** Add keyboard-reachable navigation to every planned control family.

**Acceptance:** Navigation links target the five labelled family destinations and remain usable without a pointer.

**Evidence:** `npm run build` result and changed-file list; browser focus validation is CG-M1-04.

### CG-M1-03.4 — Reduced-motion setting

**Owned paths:** `apps/lab/src/MotionSetting.tsx`.

**Outcome:** Add a reduced-motion setting that changes gallery motion without hiding content.

**Acceptance:** The setting exposes its state accessibly and changes an application-level motion attribute; no content is conditionally removed.

**Evidence:** `npm run build` result and changed-file list; browser behavior validation is CG-M1-04.

### CG-M1-03.5 — Responsive gallery layout

**Owned paths:** `apps/lab/src/GalleryLayout.tsx`, `apps/lab/src/styles.css`.

**Outcome:** Add narrow and wide gallery layout plus visible keyboard focus.

**Acceptance:** The shell presents at narrow and wide widths without horizontal overflow; keyboard focus is visibly distinguishable; CSS uses the shipped skin values rather than a second token source.

**Evidence:** `npm run build`, manual narrow/wide screenshots, and changed-file list.

### CG-M1-03.6 — Reusable example frame

**Owned paths:** `apps/lab/src/ExampleFrame.tsx`.

**Outcome:** Add a reusable empty example frame with slots for later control examples.

**Acceptance:** The frame accepts a title, description, and child content; it does not create a concrete Core v1 control.

**Evidence:** `npm run build` result and changed-file list.

### CG-M1-03.7 — Gallery integration and handoff

**Owner:** Coordinator.

**Owned paths:** `apps/lab/src/GalleryApp.tsx`.

**Outcome:** Assemble the accepted sub-packets, record build evidence and narrow/wide screenshots, and prepare the CG-M1-04 test handoff.

**Acceptance:** Gallery has family navigation, a visible title/description, keyboard-visible focus, a reduced-motion setting, narrow/wide layout, and reusable example-frame slots. No concrete Core v1 controls are introduced.

**Evidence:** production build, manual narrow/wide screenshots, and specification handoff notes for CG-M1-04.

## CG-M1-04 — Browser smoke specifications (local agent eligible)

**Objective:** Add browser coverage for direct gallery load, family navigation, keyboard focus, and reduced-motion behavior.

**Owned paths:** `tests/**`, `apps/lab/**/*.spec.*`.

**May consume, not edit:** gallery shell, package configuration, and all package source.

**Non-goals:** Rewriting gallery implementation to make tests easier.

**Acceptance:** Tests exercise the running gallery—not a mocked DOM—and fail if navigation, focus indicator hooks, or reduced-motion state disappear.

**Evidence:** exact browser-test command and unedited result captured in the M1 ledger.
