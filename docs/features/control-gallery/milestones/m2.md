## Acceptance criteria

- Labels, descriptions, errors, and required semantics are programmatically connected.
- Invalid input announces the problem; correction preserves the current value.
- Controlled and uncontrolled examples behave as documented.
- Form reset restores the documented initial values.
- Keyboard focus and long-label/narrow-width behavior are covered.

## Invariants

- An invalid field cannot claim valid submission.
- An error never clears a user-entered value by itself.
- `Field` owns field-level labelling and error association; controls do not duplicate it.
