# Library quality foundation

## Outcome

Foundry has one reviewed control contract, an approved Base UI implementation foundation for every Core v1 control, a fully scoped token and skin model, canonical product gates, and an installable package boundary. Existing controls have bounded correction dispositions before feature work resumes.

## Included

- define the Base UI primitive or rendering-foundation mapping for every Core v1 control, its capability dispositions, private adapter boundaries, production sequence, and representative verification journeys in [Base UI production integration](../base-ui-integration.md);
- establish the per-export public and migration boundary in [Core v1 control contracts](../control-contracts.md), including owned hooks, controlled state, focus, localization, heading composition, and safe native props;
- define the exact token schema, owned parts, shared recipes, portal-safe scope, validators, and rendered approval in [Token and skin contract](../token-and-skin.md), replacing implicit and consumer-wide CSS effects;
- define package output, peer dependencies, supported runtimes, canonical commands, and pull-request checks; and
- turn each accepted correction into a small Maestro-ready implementation outcome with observable assertions and gates.

## Completion evidence

Architecture fidelity, completeness, and consistency reviews pass. The Base UI integration contract covers every Core v1 control without exposing its API, retains the current Foundry `Select` name while replacing its native implementation, and records the disposition of every relevant Base UI 1.8.0 capability. The per-control, package, gate, token, and skin contracts are detailed enough for bounded implementation without inventing behavior.

## Status

Architecture in progress. Implementation has not started.

The all-control Base UI correction is one architecture checkpoint, not completion of this stage. Exact package exports, built-file layout, canonical commands, CI/release matrices, and packed-consumer entrypoints remain the next delegated technical subject under `CG-ARQ-005`; their absence is an accepted deferral for this checkpoint and still blocks implementation readiness.
