## Routing forecast

M4 targets **60–70% accepted local code-bearing lines**. Overlay foundation, Dialog, Menu, public exports, gallery integration, and the highest-risk focus specification remain coordinator-owned; local packets are limited to one control or one test behavior group.

## Acceptance criteria

- Dialog and Drawer trap/contain focus as specified, close on Escape, and restore focus to their trigger.
- Popover and Menu use their documented outside-dismissal behavior and do not leave orphaned open state.
- Tabs support pointer selection and Arrow-key movement, with one selected tab and one visible panel.
- All overlay and navigation examples work at narrow and wide widths.

## Invariants

- No hidden overlay retains focus.
- Closing an overlay restores focus to its last valid trigger.
- Exactly one tab panel is visible for each tab set.

## CG-M4-01 — Overlay foundation contract

**Entry:** A later overlay component renders inside `OverlayRoot`, captures its invoking element before opening, and calls `useOverlayLayer` while open. The foundation records layers in last-in-first-out order; a layer can tell whether it is the active top layer.

**Exit and recovery:** Removing the active top layer attempts one focus restoration to its captured trigger. Restoration succeeds only when that trigger is still connected, enabled, and not inside an inert ancestor. If the trigger is gone or unavailable, the foundation does not invent a fallback target, focus the document body, or throw; the later control owns any workflow-specific fallback. Removing a non-top layer does not steal focus from the active top layer.

**Alternate paths and refusal:** Opening without a captured trigger records no trigger and therefore has no restoration target. A missing `OverlayRoot` is a programming error and throws before registration. This packet does not render a visible layer, establish `dialog`/`menu` semantics, add a portal/backdrop, process Escape or pointer dismissal, or impose a focus trap; later component packets opt into the exported helpers according to their approved behavior.

**Shared helpers:** The foundation supplies focusable-descendant discovery, first-focus placement, and a Tab/Shift+Tab cycle helper. Helpers ignore disabled, hidden, and inert descendants; first-focus returns false when there is no focusable target. Modal containment and initial-focus choice are exercised by Dialog/Drawer, not assumed by every overlay.

**Validation:** Foundation jsdom tests prove active-layer ordering, captured-trigger restoration, stale/disabled/inert trigger refusal, non-top removal, focusable filtering, no-target initial-focus result, and Tab-cycle boundaries. TypeScript, static check, production build, source scope/diff checks, and independent review are required. Browser behavior is `UNTESTED` in this packet because no gallery-facing overlay exists until later M4 packets.

## CG-M4-02 — Dialog contract

**Entry:** `DialogRoot` provides controlled `open` or uncontrolled `defaultOpen` state and `onOpenChange`. `DialogTrigger` is one native button; it captures itself before requesting open and exposes the current expanded state and dialog relationship. `DialogContent` renders only while open, requires a visible `title`, and uses a named native `<dialog>` with `showModal()` for the platform modal layer. `DialogClose` is the catalogue-labelled native close action.

**Exit and recovery:** Escape or `DialogClose` requests `onOpenChange(false)`. In uncontrolled use this removes content; in controlled use the parent owns the visible state transition. M4-01 then restores focus only to the valid captured trigger. A native close event also reports a close request. Outside-pointer clicks do not dismiss the dialog. Reopening after close creates a new open layer and receives initial focus again.

**Alternate paths and refusal:** `open` and `defaultOpen` conflict and refuse before rendering. A missing `OverlayRoot` is a programming error. A disconnected, disabled, or inert trigger leaves focus unchanged on close rather than choosing an arbitrary fallback. A content instance with no focusable descendant remains focusable itself so Tab cannot leave the modal layer. Dialog does not expose alert-dialog semantics, portals, custom backdrop behavior, timeout/auto-close, consumer role/style/class escapes, Drawer/Popover/Menu behavior, or a public package export.

**Validation:** Dialog jsdom tests prove controlled/uncontrolled entry, conflict refusal, trigger states, native named dialog semantics, initial focus, Tab/Shift+Tab containment, Escape and explicit-close request behavior, outside-click refusal, repeated open/close, valid and stale-trigger recovery, and no-focusable-content containment. TypeScript, static check, production build, source scope/diff checks, and independent review are required. Real browser behavior is `UNTESTED` here because CG-M4-16 owns the gallery-facing Chromium specification.

## CG-M4-04 — Popover local packet

**Writable paths:** `packages/react/src/overlays/popover/**` only. **Estimate:** 100–140 code-bearing lines, including its focused jsdom test. **Prerequisites:** merged M4-01 foundation; M4-02 and M4-03 may be read for established compound-control conventions but not edited. **Non-goals:** Dialog/Drawer/Foundation changes, public exports, skins, portals, custom backdrop/animation, a document click-away simulation, gallery examples, and browser specifications.

**Required behavior:** Implement internal Popover root, trigger, content, and close parts. The root supports controlled `open` or uncontrolled `defaultOpen` (never both); controlled use requires `onOpenChange`. The trigger is a native button that captures itself and owns `aria-controls` and `aria-expanded`. The content requires a visible `title` wired through its fixed `aria-labelledby`, has fixed `role="dialog"` without `aria-modal`, `data-control="popover"`, `data-open`, and native `popover="auto"`; it must request close only when a native `toggle` event reports the closed state. If a controlled parent leaves `open` true after that request, re-show the native popover after React processes the unchanged controlled value; never leave React-open content platform-hidden. Native auto-popover owns Escape and light/outside dismissal. Popover is non-modal: it does not move initial focus or trap Tab. Explicit close and native dismissal request false once; the root then removes content and M4-01 restores only a valid captured trigger. Default-open/no-capture and stale-trigger close paths invent no fallback. Runtime consumer `className`, `style`, `role`, `aria-modal`, `popover`, `aria-labelledby`, and fixed data hooks are refused.

**Observable assertions:** (1) trigger opens one named, non-modal auto Popover with the exact title relationship, fixed role/no `aria-modal`, `data-control`, `data-open`, and expanded/controls state; (2) explicit close and a closed native-toggle request false once, while the native auto mode is visible as the documented outside-dismissal path; (3) controlled and uncontrolled entry/recovery work, controlled-without-callback and mixed state modes refuse, and unchanged controlled `open=true` re-shows after native dismissal; (4) Popover neither moves focus on opening nor traps Tab; (5) valid, stale, and no-capture recovery plus runtime escape refusal are visible in focused tests.

**Required gates:** focused Popover test, `npm exec tsc -- --noEmit`, `npm run check`, `npm run build`, `git diff --check`, and one required scoped commit. Return the exact changed-file list, unedited command results, `PASS`/`UNTESTED` paths, and blocker if a required rule is absent. ## CG-M4-05 — Menu coordinator packet

**Writable paths:** `packages/react/src/overlays/menu/**` only. **Prerequisites:** merged M4-01 foundation. **Non-goals:** changes to existing overlays/foundation, public exports, skins, gallery, browser specifications, submenus, typeahead, menu checkbox/radio/separator variants, portals, or animation.

**Required behavior:** Implement internal `MenuRoot`, `MenuTrigger`, `MenuContent`, `MenuItem`, and `MenuClose` precisely as decision 21. Menu is a non-modal command menu with a roving focus model: exactly one item has `tabIndex=0`, all other items have `tabIndex=-1`, and disabled items remain focusable with `aria-disabled="true"` but never activate. Trigger and Arrow/Home/End keyboard paths target every item. An enabled item calls consumer `onClick` first; a prevented event stops there; otherwise it calls `onSelect` once and requests close once. Escape and explicit close restore a valid trigger. Outside pointer dismissal and Tab close after clearing trigger restoration; Tab is not prevented. Controlled/uncontrolled conflict refuses, controlled use requires `onOpenChange`, stale/no-capture recovery invents no focus target, and all fixed semantic/state/style hooks reject runtime consumer overrides.

**Observable assertions:** (1) trigger semantics, labelled menu, first/last entry, and exact roving tab-stop state; (2) Arrow, Home, End, Enter/Space operation, including focusable disabled-item refusal and `onClick`/prevent/`onSelect`/close ordering; (3) Escape and explicit close restore, while outside pointer keeps pointer focus and valid/stale/no-capture paths are explicit; (4) Tab's non-prevented exit/no-trigger-restoration path; (5) controlled/uncontrolled/refusal/runtime-escape paths.

**Required gates:** focused Menu test, full React package suite, `npm exec tsc -- --noEmit`, `npm run check`, `npm run build`, full existing browser suite, `git diff --check`, and independent review. Menu browser behavior is `UNTESTED` until CG-M4-19.
